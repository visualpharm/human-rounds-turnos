- **Admin queue = a list plus a detail pane, not a stack of cards (2026-08-05 design-loop pull, handoff "Pinamar Admin Solicitudes Linear" — do not relitigate the shape).** The pendientes view was ten ~400px cards per page behind a pager; it is now a dense 34px-row list on the left and ONE open request in a 428px pane on the right. - **A request's doctor is ONE pair, identified by id (2026-10-23, problems.md №3 — do not relitigate).** `assigned_doctor_id` is the source of truth; `assigned_doctor` is the catalog's name for that id. Every write goes through `doctor_appointments.resolve_pair(nombre, id)`: a known id brings the catalog name; a bare name keeps an id only if it resolves to exactly ONE catalog doctor (and takes the catalog spelling); anything else is the name as given with id NULL — never an older doctor's id under a new name. `db_booking.approve` writes the pair whole (`CASE WHEN` either came, else untouched — the old per-column `COALESCE` is gone); `/assign`, the auto-suggested doctor and the HSI resolver (`hsi_resolver._asignar_profesional` → `db_hsi.assign_doctor_hsi(..., medico_id=)`) go through the same rule, so a doctor HSI booked who is in the catalog keeps its id (still in «Mis pacientes» and under `booking_requests_doctor_slot_uniq`). Reads that IDENTIFY the doctor go by id, with the stored name only for legacy rows without one: the busy-minute check (`_doctor_appointments_at_time` via `doctor_appointments.same_doctor`), the suggestion's taken slots (`_approved_by_doctor_art` keys `id:<id>` / `nombre:<norm>`), desk overbooking suggestions, `count_appointments_of` (name counts only `assigned_doctor_id IS NULL` rows; `slot_doctor_id` counts too), «Mis turnos»/«Mis pacientes» (already id-first). Reads that SHOW the name prefer the catalog's by id (`doctor_appointments.display_name`: the patient's request list/card, emails; the panel already did via `medicoEtiquetaDe`, and `medicoPorDefecto` now recognizes the assigned doctor by id). Renaming a doctor: `db_catalog.catalog_upsert('medicos', …)` rewrites `assigned_doctor` of every row with its id in the same transaction (emails, HSI hints, reports and the panel search read the stored name); a rename shipped in a pack (no DB write) is caught by the display reads and fixed in storage by `scripts/medico_por_id.py` (dry-run by default; `--apply` fills ids of name-only rows that resolve to one doctor and rewrites names that differ from the catalog, in one transaction; ambiguous/unmatched names and ids the catalog no longer has are only reported, by request id). `day_queue_events` keeps its snapshot pair as written (event history).
