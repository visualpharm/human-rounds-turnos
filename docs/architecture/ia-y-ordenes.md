# AI order reading, prompts, abuse limits, solutions

Extracted from CLAUDE.md 2026-07-29 (verbatim). These are load-bearing decisions — **do not relitigate** what is marked as such. Read this file before touching the code it describes.

- **"Upload your order" (2026-07-16, ex "How to prepare", R4): `preparacion.py` + `abuso.py`.** An account-free assistant and IS a menu item (nav.js `orden`): `GET /preparacion[?service=<id>]` (`chrome="focus"` reusing `hospital._shell`). The client (`upload-order.js`) no longer uses its own endpoint — `POST /api/preparacion` DIED: it uploads the order to `POST /api/analyze-order` (3-pass, persists `pending/<token>` for 48 h) and builds from the response (1) "Your order requests" (`ai.campos.practicas`), (2) **"Where to get the appointment"** — matches each practice against the catalog with `SanaSearch.buscarFrase` (degrades over the phrase's tail + the level with the best average tier wins: "Ergometría de 12 derivaciones" has to surface the Ergometría service FIRST, not Cardiología by keyword; test in `search-match.test.mjs`) and draws listing.js rows with `SanaSearch.servRow` (shared builder, formerly `index.html:servRow`; `opts.extraQuery` appends `order=<token>` ONLY to bookable hrefs), (3) prep-cards (`ai.preparacion`, matched IN CODE against `webdata/estudios-preparacion.json`; `ai.preparacion_no_reconocidos` excludes the specialty read — it's not a study that requires preparation). Handoff to the wizard: sessionStorage `st_order_pending` {token, ai, filename} + `?order=<token>` in the URL — `service.js` validates it against storage, sets `wiz.token/wiz.ai`, removes "Your order" from the counter, and starts at Cuándo (with `?slot=` it lands directly on Tu cuenta); on Confirmá the order is shown by token as filename + "Cambiar" (no in-memory preview). WATCH OUT: listing.js APPENDS its slot to the host: clear `el.innerHTML=""` before re-rendering or the spinner is left sitting above the table. `abuso.py` remains the anti-abuse layer for `/api/analyze-order` (rate limit 10/hour and 30/day per IP, envs `TURNOS_AI_PER_HOUR`/`TURNOS_AI_PER_DAY` + Turnstile — any new client MUST import and mount the named exports from `static/platform/turnstile.mjs` on retry screens). Shared upload control `wz-upload.js`. `ai_orden.leer_estudios` was left without a UI consumer (don't delete without grepping).
- **Requests with an order**: JSON POST with the order in base64 (`{filename, mime, data_b64}`) — NOT multipart (cgi died in py3.13). File goes to `data/ordenes/` (runtime volume, do NOT commit data/). **Postgres, not SQLite** (the product owner's decision). db.py imports psycopg lazily and degrades to 503 — the server always boots.
- **AI = Gemini 3 Flash via OpenRouter, ONE reading (2026-07-19, product owner: "One reading with Gemini Flash 3. That's it." — reverses the 3-pass design)**. `ai_orden.py:analizar_orden_3pass` keeps its name for the call sites but does a single read (`_TEMP=0.2`, model `google/gemini-3-flash-preview`); `_verdict_3pass` still reconciles N readings in code, with N=1 — the "N/N lecturas coinciden" phrase only renders when N>1. Verdicts: `parece_correcta`/`dudosa`/`ilegible`/`documento_equivocado` (es_orden=false → "parece {tipo_documento}," e.g. "una factura de peluquería canina")/`revision_manual`. ~$0.001/order. `TURNOS_FAKE_AI=1` = no network (filename containing "factura" → documento_equivocado, to test the flow). Total failure → `revision_manual`, never blocks.
- **Identity: account-vs-order (2026-07-11, do not relitigate):** the header of the admin card is the requesting ACCOUNT (tag "cuenta"); the order must be in the account holder's name (`campos.paciente.coincide`, accent-stripped tokens, tolerant of inverted last-name/first-name). The **DNI is only compared if the order CARRIES a legible one** — handwritten ones usually don't, and the **health-coverage member number (Swiss "800.006-3055088 01 0001," OSDE "62 865209 0 01") is NEVER a DNI** (rule baked into the prompt; DNI = 7-8 digits): no DNI read → `coincide=None`, not a false "doesn't match." A **práctica** that IS the requested service validates the specialty (an order asking for "Ergometría" is valid for the Ergometría service even if the AI infers "Cardiología"). Matrícula: a stamp can carry TWO numbers ("M.N. 104512 - M.P. 90871") — REFEPS looks up the FIRST one; the dots are thousands separators ("57.093"→57093).
- **The patient gets the SOLUTION, never the error (2026-07-27, product owner): `soluciones.py`.** A rejection that only says "your order expired" leaves the patient exactly where they were. `remedio(row, motivo)` maps each canonical rejection cause to the NEXT CONCRETE STEP with **deep links, never the homepage**: expired/unsigned order → a Medicina general turno (that's who writes a new order, and it needs no order itself) with its first 3 free slots, each link `/service/<id>/book?slot=<dia>T<hora>` landing on the wizard with the slot already chosen; wrong specialty → the service the order actually asks for, with its slots; illegible / not-an-order / someone else's name → `/upload-order?service=<id>` to re-upload without redoing anything; no slots / not done at this center → the same service at ANOTHER center (the district's centers are ~10 min apart, so travelling beats waiting — same doctrine as choosing a study by wait). Slots come from `hospital._turnos_servicio`, the SAME function behind the patient's grid, so an email can never offer a turno the site won't then allow. `notificaciones.notificar_rechazada` leads with the remedy (the subject line too — it's all that's read on a phone) and `_rechazo_whatsapp` sends it by WhatsApp as well, but ONLY when there IS a remedy: a WhatsApp that just delivers bad news is noise. No remedy for that cause → the plain old notice, never an invented one. Best-effort at every edge: the rejection already persisted when this runs.
  - **`servicio_sugerido` prefills the reassignment combo (same module, one source of truth).** `solicitudes._admin_row` exposes it, and a queue card whose order is for another specialty renders with "Derivar a" ALREADY OPEN and set to the service the order names (the product owner: "show and prefill the reassignment dropdown"), doctors re-filtered to the destination. The operator derives where the patient's email points because both call the same function. `buscar_servicio` is the Python mirror of search.js (same `variantes`/tiers) and the matching is deliberately conservative, because the prefill CHANGES what gets approved: candidate phrases are scored SEPARATELY (`frases_de_orden` — one concatenated phrase degrades from the tail, so the specialty, which sits last, was never searched and a leftover meta-word like "consulta" matched anything); a phrase degraded down to trámite words only is skipped; a match must reach the service's NAME (`_TIER_MAX_SUGERENCIA`, tier < 3) so a CATEGORY like "Diagnóstico por imágen" stops proposing "Ecografía infantil"; and a práctica naming a study the hospital does NOT do vetoes the suggestion entirely — offering an ecografía for a resonancia is worse than offering nothing. That not-offered list is `webdata/estudios-preparacion.json:_meta.no_ofrecidos_…`, corrected the same day: **PAP and fondo de ojo came OFF it** (PAP is listed by 16 services, fondo de ojo by Oftalmología — telling a patient "no se realiza" for the commonest gynecological order was a hard bug); synonyms with a sub-3-letter content token are dropped (`"rm de"` → the token `rm` is inside deRMatología/enfeRMo and would veto half the catalogue; `rmn`/`eeg`/`dxa` stay). Tests: `tests/test_remedies.py`, `tests/test_no_ofrecidos.py`.
  - **One-click fixes, worded as the patient's way out (`ARREGLOS`).** A card with a detected problem grows up to two quiet buttons that pick the standard motivo and reject in one gesture, routed through the real Rechazar button so the shortcut changes the number of clicks, not the logic. The label says what the patient RECEIVES — "Ofrecerle turno con Medicina general", "Pedirle una foto más nítida" — never the error they made.
  - **"Two spellings of the same" was two CENTERS (the product owner's screenshot).** The Derivar combo showed two identical "Psiquiatría" rows; they are CAPS Pinamar and CAPS DiabetPin. `svcCombolItems` appends the centre **only to names that repeat** (adding it to the other 98 would widen the control for everyone — control-content-fits), and `comboHtml` now measures that subtitle for width while still excluding the médico combo's "— libre <cuándo>", which lives only in the dropdown. The combo also filters through `SanaSearch.buscarConPuntaje` instead of raw substring — the order says "psiquiatra"/"cardiólogo", the catalogue says the specialty — with the service's `palabras` searchable but not shown, and substring kept as a net.
  - **An empty dropdown explains nothing (`NO_SE_REALIZA`).** Typing "resonancia" returned zero rows, indistinguishable from a typo. The 8 studies the hospital doesn't do now say so and name the way out; the list mirrors the JSON above and `test_no_ofrecidos.py` fails if the two drift.
  - **Catalogue tagging: +964 `palabras` across 114 services.** `papanicolaou` (the correct spelling) matched **zero** services — the data only had `papanicolau`; no lab analyte was searchable (`hemograma`, `TSH`, `urea`, `perfil lipídico`, `PSA`, `VDRL` → 0 hits, now 4-8); same for `EKG`, `artrosis`, `hernia inguinal`, `doppler venoso`. Professional nouns were deliberately NOT added — `search.js:variantes` already derives them.
  - **Still open — REAL duplicates, needs the hospital's word:** an audit found 8 high-confidence same-centre duplicate pairs (`laboratorio-hospital`/`extracciones-de-laboratorio-pinamar`, both testeo-rápido pairs, both anticoncepción/medicina-general-anticoncepción pairs, `ive-ile-ostende`, the embarazo courses, and `psicomotricidad-ostende`/`consultorio-psicomotricidad-ostende` — which contradict each other on `modo`, one of the two lying to patients). Deliberately NOT deleted: the Secretaría still owes the definitive Excel ("lo que no está acá no existe"), and removing a consultorio that does exist is worse than a duplicate row that now shows its centre.
- **PDFs get converted to PNG before the model** (`_pdf_to_png`: pdftoppm in Docker/poppler, sips on macOS). OpenRouter's file-part requires a minimum balance (402 "requires at least $0.50 in balance for files") — the image route doesn't. No converter available → tries file-part → `revision_manual`.
- **`extract_json` tolerates LISTS of documents**: a real photo can carry two prescriptions (a receta + a study request) and the model returns an array despite the prompt; the element that looks most like an order gets picked (`_doc_score`). Discovered with the real ergometría order (2026-06-16); without this, all 3 passes parsed `{}` and everything fell into revision_manual.
- **The AI's instructions are editable from the panel: `prompts.py` + admin section «Instrucciones de la IA» (2026-07-28, product owner).** Every prompt used to be a constant inside the module that called it, so changing a reading rule — "don't confuse the member number with the DNI", "an order a year old is expired" — was a deploy. Those rules belong to the hospital, not to whoever writes the code. Same overlay pattern as `catalogo.py`: the original lives in `prompts.REGISTRO`, the `prompts_ia` table overrides it, "Restaurar el original" deletes the row. Four prompts: `orden_analisis` (ai_orden's order reading), `orden_estudios` (the cheap studies-only read), `chat_sistema` and `chat_anonimo` (chat_agente). Deliberately NOT included: `ocr_dni.py`'s prompts — authentication goes through RENAPER, not a DNI photo, so they are not hospital rules.
  - **The canonical is ENGLISH; what gets edited is the Spanish.** What is sent to the model is `texto_en`; the panel shows a translation (`texto_es`), which is what hospital staff edit. On save a **three-way merge** runs (`prompts.fusionar`): the stored Spanish is diffed against the edited Spanish and ONLY the changed paragraphs are translated back and overwritten in place — untouched paragraphs keep their English word for word. Without that, every save would be a full re-translation and the text would degrade on its own, trip after trip; the JSON block (which the code parses by key name) would break on the first one. A paragraph that merely MOVED is recognized by its Spanish (map `conocidos`) and never re-translated. Paragraph-level alignment between `texto_en` and `texto_es` is the precondition for all of it, so translation asks for an explicit `@@@` separator and verifies the count — if the model doesn't respect the structure the prompt is flagged `alineado:false` and the editor switches to editing English directly, never merging blind.
  - **Guard rails, because a prompt decides whether an order gets approved.** `obligatorias` per prompt (every JSON key name, `{hoy}`, `[opciones:`, `[login]`, the tool names): a save that drops one is rejected with the missing piece named — silently deleting a key leaves the order reader returning nothing, and that surfaces only when a patient complains. Every prior version is archived in `prompts_ia_historial` ("Versiones anteriores" → "Volver a esta versión"). After saving, the panel shows each changed paragraph's English before/after: the only way someone who wrote in Spanish can check what actually gets sent.
  - Variables are substituted by **literal token replacement, never `str.format`** — the prompt is full of JSON braces and is edited by people; `format` would need them all doubled and would blow up with a KeyError on the first edit. `texto()` caches overrides 3 s and falls back to the code original if the DB is down: the AI never stops working because of this table. The translator's own prompt (`_SYS_TRADUCIR`) stays in code on purpose — it is the machinery that makes editing possible, not a business rule. `TURNOS_FAKE_AI=1` translates without network (marks the target, keeps the alignment). Routes `/api/admin/prompts*` are `solo_admin`. UI: `admin-prompts.js` (`#prompts` list, `#prompts/<clave>` editor) — content-hash fingerprinted (`ADMIN_ROOT_JAVASCRIPT`), nothing to bump on change. Tests: `tests/test_prompts.py`.
  - **AI limits count per browser, and only while the AI can answer (the product owner, 2026-10-28, after salud's «Hiciste varias consultas seguidas»).** salud has no `OPENROUTER_API_KEY` and its patients share one gateway IP, so the per-IP 10/h counter tripped for the whole hospital on calls that never reached a model. Now: (1) `ai_health.available()` false (no key, `TURNOS_AI_DISABLED=1`, breaker open) → `_analyze_referral_core` skips `abuse_guard.allowed`, `ai_costs.blocked` and `ai_cooldown.attempt`; the order is saved, `ia_disponible:false`, verdict `pendiente_ia`, and the patient gets the next step, never a 429. (2) With the AI on, the limits key on `abuse_guard.identity(ip, headers)` = `ip|<X-Turnos-Client>` (the id `wz-upload.mjs`/`chat-widget.mjs` keep in localStorage `stz_client_id`, 16–64 `[A-Za-z0-9_-]`); no/ malformed header = the bare IP (strict bucket). (3) A ceiling on the whole IP (`abuse_guard.ceiling_ok`, `TURNOS_AI_IP_CEILING_PER_HOUR` 200 / `_PER_DAY` 600; chat `TURNOS_CHAT_IP_CEILING_PER_HOUR` 200) caps id rotation; **0 (or less) on a ceiling means no ceiling** (29.10; it used to refuse every request), and 0 on both AI ceilings records nothing. `abuse_guard.allowed(ip)` and `chat_api._allowed(ip)` keep their signatures (golden `ip_limiters`). The chat launcher is not rendered without a key (`_chat_bootstrap.html`, `ai_chat_configured()`); with a key but a provider outage the chat answers with the `assistant.outage` remedy (short phrase + Servicios and Centros links). Proofs: `tests/test_ai_sin_clave_limites.py`.
  - **`enfriamiento_ia.py`: escalating per-identity cooldown on image/PDF analysis (the product owner, 2026-07-23), layered ON TOP of the existing coarse IP limits (abuso.py 10/h+30/day, costos_ia.py garbage-detection).** Each identity (`"dni:<dni>"`/`"tel:<tel>"`/`"ip:<ip>"`) gets a burst (`TURNOS_IMG_BURST`, default 2) of free analyses; past the burst, each further one requires a minimum wait since the previous that DOUBLES — 1 min, 2, 4, 8, 16…, capped at `TURNOS_IMG_CAP_MIN` (default 64 min) — and the counter decays on its own after 24h of silence (fresh burst). `intentar(identity, now=None)` both checks AND registers in one call (call exactly once per real analysis attempt); `chat_tools.analizar_orden_para(identity, ...)` is the single choke point that gates + calls `solicitudes.analizar_bytes` — used by the MCP/chat `analyze_order` tool AND by `whatsapp_chat.py`'s media path (both providers). `solicitudes._analizar_orden` (the web `POST /api/analyze-order`) also got this layer, keyed by IP (anonymous surface, pre-registration) — `abuso.py`'s existing gates stay untouched, this is an added layer, not a replacement. `solicitudes.analizar_bytes` itself is the pipeline EXTRACTED from `_analizar_orden` (persist file, run `ai_orden`, match preparation, save pending meta, `costos_ia.registrar`) — the web endpoint is now a thin wrapper around it, and MCP/chat/WhatsApp call it directly instead of re-implementing "analyze an order."
