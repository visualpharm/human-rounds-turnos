Extracted from CLAUDE.md 2026-07-29 (verbatim). These are load-bearing decisions — **do not relitigate** what is marked as such. Read this file before touching the code it describes.

- **«Confirmá»: the phone typed there is the TURN's; the account changes only with «Guardar también en mi cuenta» (2026-10-24, the product owner's hub).** `wiz.contactoTurno` holds the number and `submit()` sends it as the request's `contacto`; leaving the field no longer writes the account (a ticked phone is written only at «Enviar», which waits for any half-finished save of another field). The checkbox is offered only while the typed number differs from the account's (compared with `Format.telNacional`, so `+54 9`/`15`/spaces are the same number), starts unticked, and the account is always the booking person's, also for a child. An account with no phone is filled (no checkbox); `/api/account/update` is called only when the step changes something of the account (`cuentaAActualizar`). Entry in `docs/decisions/2026-10-w4d.md`, tests `tests/service-confirma-telefono.test.mjs` + `tests/e2e/confirma-telefono.spec.mjs`.
- **Informational service page + direct wizard (2026-07-12, do not relitigate).** In `solicitud`/`solicitud_con_orden` modes: `/service/<id>` = an INFORMATIONAL, doctor-style page (breadcrumb + first-appointment band, "How it works" = signage+PAMI, preparation, "Where you're seen" with address/phone/office/age, weekly grid `data-semana` if `horario` is real — "Con turno, según agenda" gets filtered out as a placeholder; "Who attends" only on specialty clusters, never on `diagnostico` because different studies coexist there); the wizard lives at `/service/<id>/book` and ALL action links across the listings (`hospital._turno_href`: name, row, appointment pill, doctor CTA, "Get an appointment with a GP," the home search) go STRAIGHT to the wizard with no toll page (the product owner: "lead it directly to the wizard"). The first free slot **IS** the button — since 2026-07-14 with the SAME wording as the listing cell: verb + date (`Sacar mañana, 07:30` / `Sacar el viernes 17 de julio, 13:00`, helpers `_sacar_label`/`_cta_bucket`, color by proximity `mp-cta--{ya|semana|lejos}` = the same greens/ambers/taupes as listing.js), links to `/service/<id>/book?slot=<dia>T<hora>` and arrives preselected at the "Cuándo" step; next to it, deliberately quieter, "Más horarios" (`.mp-cta-2`, outline — same name as the listing cells' link: one action, one name; RIP "Elegir otros horarios"). **"Más horarios" leads to CHOOSING the appointment, not to uploading the order (2026-07-15):** it points to `/service/<id>/book?slots=1` and with that flag the with-order wizard REVERSES the steps (Cuándo → Tu orden → Tu cuenta → Confirmá; `service.js:ELEGIR_PRIMERO`). Load-bearing decisions: (1) **No visible clock.** The hold is 3 min with a session open and 10 without (`slot_holds._TTL_LOGGED_IN_MIN`/`_TTL_ANON_MIN`, decided per-request by `_ttl_for`) — confirming takes seconds, so a running counter only rushes someone who doesn't need rushing. The remaining time always comes from the **`ttl_min` the server returns** on `holdTomar` — never a number written client-side. ## Máximo de turnos activos por paciente (`booking_limits.py`, 2026-08-01)

The product owner: *"create an option for the whole website, and per doctor apart, for the
maximum number of turnos one can get. For kinesiología it could be ten, and for
most specialties just one."*

**Por qué es un número y no un booleano.** Una consulta de especialidad es UN
turno: tres cardiologías abiertas de la misma persona son casi siempre un
mis-click o un seguro contra la lista de espera, y cada una es un lugar que
nadie más puede tomar. La rehabilitación es una SERIE: kinesiología son diez
sesiones por definición, y un límite de uno convierte el caso normal en un
error.

**Resolución, de lo más específico a lo más general** — `booking_limits.limit_for`:

    override del médico → override del servicio → default del sitio

- Médico y servicio comparten el MISMO campo de catálogo, `turnos_activos_max`
  (`catalog._normalizar_turnos_max`). Vacío = hereda; un 0 se rechaza, porque
  "cero turnos" no es una regla que nadie quiera.
- El default del sitio es `MAX_ACTIVE_REQUESTS` (config, 1), editable en
  **Configuración → Turnos** (`settings_admin._guardar_turnos`).
- El panel lo edita en la ficha del servicio y en la del profesional, con el
  mismo control ("Turnos por paciente", `cnt-in cnt-num`, placeholder = el
  default heredado).

**Qué cuenta.** Sólo lo que ocupa lugar ahora: pendientes + aprobadas con turno
futuro, del MISMO DNI clínico (los turnos de un hijo son del hijo, no del padre
que los sacó) y el MISMO servicio — `db_slots.count_active_requests`. Rechazadas,
canceladas y ya atendidas no cuentan, y eso es lo que hace que la serie de
