# Decisions

Append-only, newest last. Every technical decision later work depends on, and
every decision the product owner made. Before changing an existing behavior, grep
`docs/decisions/`; contradicting a logged owner decision needs the owner's Yes.

The entries live one file per month: `docs/decisions/YYYY-MM.md`. This file
holds the rules and the index below — never an entry.

**A new entry goes at the end of `docs/decisions/<YYYY-MM>.md` for the month of
its date — today's month.** The first entry of a month creates that file with the
same header as the others (`scripts/decisions_index.py`
`month_header()`). A closed month too big for one file is cut into parts
`YYYY-MM-w<week><letter>.md` (`2026-10-w4b.md`), each under 40 KB, entries
unchanged and in the same order; the entry still goes into the file of today's
month. Then refresh the index:
`python3 scripts/decisions_index.py --write` (`test/test_decisions_index.py`
fails until it is current).

Format:

    ## YYYY-MM-DD · <title>
    Decided: … · Why: … · Rejected: … · Undo: … · By: owner | agent
    Source: <commit / file>
