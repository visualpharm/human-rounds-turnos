## 2026-10-29 · A request card cannot approve before its own doctor agenda has arrived; a 409 for a taken time refreshes the agenda and tells the desk to pick another
Decided: the card of a pending request is painted with the time the server proposed, and the doctor's real agenda arrives later (`poblarTurnoSel` → `/api/admin/appointment-slots`). Until it arrives the time select is marked loading (`data-agenda="cargando"`, `aria-busy`, disabled, one option «Cargando horarios…») and «Aprobar» is disabled from the first paint (set synchronously, lifted when the agenda answers). `executePending` also refuses to approve a card whose select still carries `data-agenda`, so no batch path can send the proposed time. A failed agenda (`slotsPara` in strict mode throws and never caches the failure) keeps «Aprobar» off and shows «No se pudieron cargar los horarios.» with a «Reintentar» button that clears the cache and asks again. A 409 `turno_tomado` / `turno_medico_tomado` clears the slot cache, asks the agenda again (`tras409`) and says «elegí otro horario» instead of leaving the stale time in the select. · Why: found 2026-10-28, an «Aprobar» pressed before the agenda arrived sent a time the doctor no longer had and got a 409 the desk had not caused · Rejected: leaving the button on and relying on the 409; a spinner without disabling the button · Undo: revert the commit · Cost: on a slow link the desk waits for the agenda before approving · Agent calls (reversible): the wording, the disabled look (45 % opacity), the failed agenda not cached · By: agent (technical choice inside the agreed slice).
Source: `admin-app.js` (`aprobarHtml`, `poblarTurnoSel`, `agendaMarcar`, `agendaFalla`, `executePending`, `slotsPara`), `static/platform/admin-solicitudes.mjs`, `locales/{es,en}/admin.queue.json`; `test/e2e/admin-solicitudes-agenda-race.spec.mjs`, `test/admin-queue.test.mjs`, `test/lineage-admin-action-error-toast.test.mjs`.

## 2026-10-29 · «Derivar a» a un servicio de otro centro: la mesa acotada ve los horarios del servicio nuevo
Decided: `GET /api/admin/appointment-slots` accepts `derivacion=1`, sent only by the Solicitudes screen (`slotsPara`); with it a desk account scoped to one center gets the slots of the derived service even when that service belongs to another center, and the card shows the new service's center instead of the request's old one. Without `derivacion` the center scope stays closed, and so do the POST that creates an appointment and the manual-appointment screen. · Why: a hospital desk derived a gynecology request to a service that the CAPS attends and got no slots (video of 2026-10-29); the empty list was the center scope applied to a service the request is about to leave; the request already moves to the new center on approval (84ecd5c6) · Rejected: opening the slots to any scoped desk everywhere (it would let a manual appointment be booked in another center's agenda) · Undo: revert the commit · By: agent.

## 2026-10-29 · A page open past the portal session goes once to the portal sign-in instead of failing its lazy imports
Decided: Sentry TURNOS-SALUD-4 («Failed to fetch dynamically imported module» on `/admin/my-patients`) is not an app fault: on salud the municipal gateway answers every request without a portal session — `/static` and `/` included — with its own 401 `{"error":"unauthenticated","login":"<portal sign-in>"}`; the app never receives it, so serving static files without a session is not ours to do. The fix is client-side: `static_fingerprint.manifest_script()` also emits `recover_script()` (`core/static_recover.js`, inline because a static file sits behind the same 401). On an unhandled dynamic-import failure or a failed module `<script>` it probes one static file and, only on that exact 401 shape with an https sign-in URL, goes to the sign-in with `return=<this page>`; one trip per 5 minutes per tab (sessionStorage), so no loop. `sanaImportStatic` (admin-shell.js) asks first and shows neither an error line nor a rejection while the page leaves. A 404, offline, the test sites' Basic Auth or a missing gateway change nothing. Lazy imports handled locally with their own `.catch` (e.g. the alerts bell) still degrade by design. · Why: the person returns to the same page signed in, no white screen · Undo: revert the commit; `manifest_script()` goes back to the bare manifest · By: agent (technical choices inside the agreed slice).
Source: `core/static_recover.js`, `core/static_fingerprint.py` (`recover_script`), `admin-shell.js`; `test/static-recover.test.mjs`, `test/test_cache_headers.py`.
