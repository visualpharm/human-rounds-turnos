## 2026-10-08 · The desk loads turnos into HSI through a Chrome extension that fills the screen, never an API
Decided: `extensions/turnos-hsi` (Manifest V3) puts «Cargar en HSI» on every «Pacientes de hoy» row and fills HSI's own «Nuevo turno» in the operator's logged-in tab. Default everywhere, production included: fill and stop — the operator presses Confirmar. After a save HSI itself confirmed, the panel offers «guardar solo» on the 1st, 2nd, 3rd, 5th, 8th and 13th save, then every 20th; only the operator's yes turns it on, the settings page turns it off, and a change of HSI address resets it. It ships with permission for the test HSI only; any other address is granted by the operator. Interface and guide are rioplatense Spanish (voseo) — the one deliberate exception to English-authored admin labels. Patient data is never logged or sent out. · Why: the province's HSI sits behind a captcha login, so the API sync cannot reach it and the desk re-typed every turno (the reference deployment's desk recording, 2026-10-08). · Rejected: calling HSI's REST API from the tab (invisible, no operator check); a hidden-tab mode (HSI's screens freeze while the tab is not drawn — the quick mode brings HSI forward, saves and returns to the list instead); answering HSI's own questions for the operator. · Undo: remove the extension; `sexo` in the day-queue payload is harmless to keep. · By: Product owner (modes, offer cadence, language); agent (the rest)
Source: `extensions/turnos-hsi/README.md`; `test/turnos-hsi-extension.test.mjs`; `extensions/turnos-hsi/test/e2e-hsi.mjs`.

## 2026-10-08 · Extension v0.2: three modes, reduced-form disk history, patient alta through HSI's own screens
Decided: the extension grows a mode setting («¿Cómo cargo los turnos?»): **botón** (default, the existing one-touch load), **manual** («Solo copiar el DNI» — the row button copies the document and opens HSI; nothing is ever typed into HSI, and a stale page asking for a load is refused), and **auto** (the operator opens the slot in HSI by hand; a DNI leaving its box fills the patient's half only if it matches exactly one turno of the last «Pacientes de hoy» on screen, held in `chrome.storage.session` — memory only). While a load runs the toolbar icon carries a small sync mark; clicking it opens a popup of the last 20 loads, newest first, stored **only** in reduced form (first name + surname initial, last three digits of the DNI, hour, outcome) — the whole DNI lives in session memory alone so a failed entry's «Abrir en HSI» can still copy it, and says so once the browser forgot. A patient HSI does not have gets HSI's own alta, half-done: the load presses the turno dialog's «Crear paciente», fills the screen it opens with what the row carries (DNI, sex, first name, surname, birth date — only empty boxes) and stops; a missing datum is named, never guessed, and the stage survives a page reload. The contact step now also picks the coverage when the row names one of the patient's coverages unambiguously — over HSI's own preselect, which is a default, not the operator's hand (the test copy preselects even with two coverages registered); without a clear match HSI's value stands, and «Actualizar Cobertura» is an action, never a coverage. · Why: Product owner's brief (2026-10-08): the desk wants to choose how much the extension types; the browser's disk must not hold identifying data beyond the reduced form; the alta must go through HSI's own screens on screen. · Rejected: creating patients through HSI's `/pacientes/new` (the test copy's component crashes at ngOnInit with `getRawValue` of undefined, and the search-page affordance needs Renaper, offline in the test copy) — the reachable path is the turno dialog's own «Crear paciente»; storing full names/DNIs of recent loads on disk; answering HSI's questions in auto mode (a question is always the operator's). · Undo: set `modo` back to `boton`; the popup and alta paths are additive. · By: Product owner (modes, reduced-form rule, alta-through-HSI's-screens); agent (the rest)
Source: `extensions/turnos-hsi/` (manifest 0.2.0, `popup.*`, `background.js`, `content-hsi.js`, `content-turnos.js`, `options.*`); `test/turnos-hsi-extension.test.mjs`; `extensions/turnos-hsi/test/e2e-hsi.mjs`.

## 2026-10-09 · A doctor's tagged window service outranks every inference
Decided: when any of a doctor's windows carries `franjas[].servicio`, the public site resolves that doctor's service from the tag (their own center first, bookable before walk-in, schedule order otherwise) for the booking button, the «Con orden» badge and the listing's Orden column. Specialty-name and cluster matching remain only for doctors with no tagged window. The doctor editor keeps the stored service while the compatible-services list is still loading, so opening and saving a doctor no longer erases the tag.
Source: hospital report by video, 2026-10-08 (a gynecologist tagged «Ginecología» showed «Con orden» and booked into a sibling service that requires a referral; the editor showed «Sin especificar» on every open); `patient_site._doctor_tagged_service`; `test/test_medico_page.py` `TestServicioEtiquetadoManda`; `test/admin-content-ui.test.mjs`.

## 2026-10-09 · Staff-created patients carry what HSI's alta needs; the desk reader waits for the whole document
Decided: `POST /api/admin/patients` requires birth date and sex next to DNI and names (the five fields HSI's own new-patient screen asks for), and a dependent saved by staff no longer defaults a missing sex to X. «Crear turno» offers «Nuevo paciente» in place when no record matches and creates the record there; a scanned document with no record opens that form with all five fields filled. The handwritten note («Anotar…») stays as the last option, unchanged. The staff «Nuevo paciente» form reads a document from any focused field (keyboard reader) or from a photo. `dni-scan.mjs` reads a keyboard reader's text only at its end (Enter, or a pause): reading it as soon as it looked like a document produced a truncated DNI and no birth date with real character-by-character readers. A Spanish-layout reader's quotes are accepted as the payload separator.
Source: owner request 2026-10-09; `admin_panel/admin_patients.py`; `static/platform/dni-scan.mjs`, `admin-create-appointment.mjs`, `admin-patients.mjs`; `test/dni-scan.test.mjs`, `test/test_admin_patients.py`, `test/admin-create-appointment-native.test.mjs`.

## 2026-10-09 · The desk completes a booking's patient data from «Pacientes de hoy»
Decided: `POST /api/admin/requests/{id}/patient-data` accepts any subset of `nombre`, `apellido`, `nacimiento` (ISO), `sexo` (F/M/X) with the same access as attendance (admin, admisionista, a doctor for their own patients; center-scoped accounts see only their center, 404 otherwise). The booking row is always written, because it is what the day queue reads. The patient's account only gains fields it was missing; a value the patient entered is never replaced through this path. Empty values are refused, never stored as an erase. The HSI extension calls it when it has to ask the operator for data HSI needs.
Source: owner request 2026-10-09 via the extension's session; `booking_requests._patient_data_core`; `test/test_booking_requests.py`.

## 2026-10-11 · Security headers and HEAD are the engine's job, not the proxy's
Decided: the app itself sends `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN` + `frame-ancestors 'self'`, `Referrer-Policy` and (over https only) a one-year `Strict-Transport-Security` on every response, and answers HEAD with the GET of the route that owns the path; the image declares a `HEALTHCHECK` on `/health`. · Why: an audit of the reference deployment found the panel login frameable, no HSTS, `HEAD /` answering 403 and the container's health unknown to the orchestrator; fixing it in the engine covers every installation, whatever proxy it sits behind. · Rejected: proxy-level headers (each installation would have to repeat them); `includeSubDomains`/`preload` (the engine cannot know what else lives under the domain); declaring HEAD route by route (the next GET route would reopen the gap). · Undo: drop the two `add_middleware` lines in `app.py` and the `HEALTHCHECK` line; browsers that saw the HSTS header keep https for a year. · Not done: the container still runs as root — moving to an unprivileged user needs the existing data volume re-owned on each installation, an owner decision.
Source: audit 2026-10-11; `core/security_headers_middleware.py`, `core/head_as_get_middleware.py`, `Dockerfile`; `test/test_security_headers.py`.
