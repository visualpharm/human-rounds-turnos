## 2026-10-28 · The web process cuts a database statement after 30 s and a lock wait after 5 s; nothing else carries a limit
Decided: the web process (`asgi_main.py` as the entrypoint, `main(web_process=True)`) sets `statement_timeout` = `TURNOS_DB_STATEMENT_TIMEOUT` (default 30 s) and `lock_timeout` = `TURNOS_DB_LOCK_TIMEOUT` (default 5 s) on every connection its pool opens (`db.enable_web_timeouts`, the pool's `configure`); `0` switches a limit off. A cut raises `db.DbTimeout`, a `DbUnavailable` subclass, so routes that already answer 503 for an unavailable database answer it for this, and the app-level handler gives the rest the same 503 with `Retry-After`. The schema bootstrap on the first connection and the backup journal's session lock run under `db.without_timeouts`; migrations (Alembic's own connection), `pg_dump`, the queue worker (a child process that never enables them, although it inherits the variables), the live-queue listener and scripts take no limit from this setting. · Why: hospital TASK-40 (variant B): a stuck lock held every panel request for as long as it lasted (docs/architecture/capacity.md, «While the database stalls»); measured on a copy grown ×300 (97,825 requests) the longest statement took 103–121 ms and the longest request 724–768 ms, so the limits are two orders of magnitude above legitimate work · Rejected: `ALTER ROLE … SET` (applies to migrations, backups and the worker too, and changes the server, not the application); connection `options=` in the URL (a pgbouncer in front refuses startup parameters, and it would override an `options` already in `DATABASE_URL`) · Undo: set both variables to `0` (no release needed), or revert the commit · Cost: a report that someday needs more than 30 s fails with a 503 until the installation raises `TURNOS_DB_STATEMENT_TIMEOUT` · Agent calls (reversible): the defaults, the names, a `DbUnavailable` subclass instead of a new status · By: agent (technical choice inside the agreed slice), hospital.
Source: `core/db.py` (`enable_web_timeouts`, `without_timeouts`, `DbTimeout`), `core/backup_journal.py`, `core/deps.py`, `asgi_main.py`, `docs/architecture/capacity.md`; `test/test_db_web_timeouts.py`.
