# `TURNOS_*` registry

Every `TURNOS_*` name the product code names (tests, vendored code and agent tooling excluded; a read, a write or a mere
reference counts): where it appears,
the default the call site passes, who is documented as setting it and what it is for. Generated by
`python3 scripts/env_registry.py --write`; `tests/test_env_registry.py` fails on a stale file, on a name read in
code that is missing here and on a name in the architecture docs that no code reads. A *family* (`NAME_*`) is a
prefix the code completes at run time; a *legacy alias* is the old Spanish name of a variable that still works as a
fallback (removing one needs to know what each installation has set); a *test seam* exists only for the test suite.
The process keys declared in `core/settings.py` are listed too when they have no `TURNOS_` prefix (`HOST`, `PORT`,
`DATABASE_URL`).

How a value is read is a property of the call site, not of the name: `config.get` / `config.get_text` consult the
panel's database override first, then the environment, then `.env` (`TURNOS_CONFIG_LOCK` freezes the override);
`<Class>.current` (`core/settings.py`) reads the environment only, or the environment and then the env file
(`DatabaseSettings`, `InstallationSettings`), never the database; `os.environ` / `_env` helpers read the environment
only.
