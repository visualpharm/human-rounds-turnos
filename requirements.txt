# Tier 4 slice 4 (docs/roadmap/tier4-replatform-design.md, "Alembic") —
# replaces migrations/__init__.py's hand-rolled apply_pending() as the
# schema-migration RUNNER. sqlalchemy.create_engine() is the execution
# vehicle Alembic's own env.py uses to run plain SQL.
# 2026-10-25: SQLAlchemy Core (never the ORM) is also the schema description
# (core/schema_model.py) and the query language of new code (core/sqlcore.py,
# which compiles a statement and runs it on the psycopg cursor db.py already
# hands out — no second pool, no Engine). ONE pin, used by the Dockerfile and
# the CI jobs alike, so Alembic's autogenerate and the app compile alike.
sqlalchemy==2.0.51

# Tier 4 slice 5 (docs/roadmap/tier4-replatform-design.md, "Background
# daemon threads -> Postgres-backed queue") — the waitlist.py sweep pilot.
# procrastinate ships a first-class periodic-task decorator matching every
# existing daemon's interval-loop shape, and its sync connector (psycopg,
# pulled in transitively via its `psycopg[pool]` extra — resolves against
# the SAME pinned psycopg above, no separate pin needed) lets the task body
# call db.py's synchronous query functions directly, no async rewrite. Its
# OWN schema is applied lazily and only when TURNOS_WAITLIST_QUEUE=1 (see
# waitlist_queue.py) — never on every boot, never part of the Alembic
# chain (design's own explicit call).
procrastinate==3.9.0
