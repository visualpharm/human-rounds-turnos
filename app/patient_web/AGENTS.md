# patient_web/ — the public patient site

- Every band or cell that promises a slot leads to a wizard that can actually offer it: the first appointment shown is the first one, not the only one.
- The patient gets the solution, never the error (`app/modules/turnos/remedies.py`): a rejection carries the next concrete step with deep links, never the homepage.
- Language is resolved once per request (`routing.dispatch()` → `i18n.bind()`) and read with `i18n.active()`; never re-resolve deeper in the stack or assume Spanish. A new server-rendered string is `i18n.t_or(key, "<castellano>", i18n.active())`, always with the Spanish fallback (`tests/i18n-fallbacks.test.mjs`).
- Translatable pack fields are listed in `pack_l10n.FIELDS` — never an id, a person's or place's name, or a string the code parses (`horario`). A service's `palabras` is the one exception: translated term by term, list stays a list, so an English query hits the matcher.
- Four i18n defects that render wrong in the other language without failing a test: translated text in a module-level constant (compute inside the render); logic keyed on rendered text instead of the wire value (id, `kind`, cluster slug); a translated word concatenated with a formatted date (use one whole-phrase catalog entry with `{when}`); an empty-string catalog key treated as missing (filter on key presence, never truthiness).
- The demo runs all ten languages with no explicit `LANG_DEFAULT`: Accept-Language decides and `?lang=` from humanrounds.org wins.
- Home-page example search chips are derived by `scripts/search_examples.py` through the real matcher into `sitio.json`; re-run it after a catalog change, never hand-write them.
- Every small round portrait comes from the one avatar atlas (`avatar_sprite.py`), named by the hash of its own bytes (never source mtimes) with the previous atlas kept for hours; only a doctor's own full-size portrait keeps its own file.
- `GET /logo.png` is served by `branding_router.py` with a plain `Response` and `If-Modified-Since` → 304, never `FileResponse`.
- Patient-site tables use one engine, `static/platform/listing.mjs`.
- The public site states inventory facts only; no measured outcome claims until real post-deployment data exists.
- The page and data code of the public site lives in `site_*.py`, one module per domain, in layers (an import never points back up): `site_base` (loader, overlay, installation clock, text helpers) < `site_schedule`, `site_shell` < `site_centers` < `site_catalog` < `site_doctors` < `site_availability` < `site_listing` < `site_page_centers`, `site_preparation`, `site_studies` < `site_news`, `site_page_doctors`, `site_page_service`. Import the module that OWNS a name and look it up at call time — `from patient_web import site_catalog` + `site_catalog._services()`, never `from patient_web.site_catalog import _services` inside `site_*.py` (a test patching `site_catalog._services` must reach every caller). There is no facade and no re-export. A new function goes to the domain it belongs to; when it needs something from a module above, move the shared piece down a layer; no module may pass 1500 lines (`tests/test_patient_site_domain_modules.py` pins the layers, the absence of import cycles, the size and the absence of the old `patient_site` module).
- The center, doctor and service-information pages are pinned byte for byte, in Spanish and in English, by `tests/test_site_page_snapshots.py` (golden `tests/golden/site_pages.json`; the render functions are cut into private `_center_*`, `_doctor_*` and `_service_request_*` helpers, none over ~80 lines). A change that moves their markup or copy on purpose: read `python3 tests/test_site_page_snapshots.py --dump DIR` before and after (`diff -r`), then re-record with `--write`; a refactor re-records nothing.
